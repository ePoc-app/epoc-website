---
title: Export HTML
description: "Exporter votre ePoc en site web statique, prêt à être hébergé (GitLab Pages, etc)."
icon: lucide:code
---

L'export HTML génère une version web de votre ePoc, lisible directement dans un navigateur, sans passer par l'application mobile. Le résultat est un site statique qui peut être hébergé sur n'importe quel serveur web (GitLab Pages, serveur local, etc).

## Exporter

::steps{level=5}
##### Cliquer sur la flèche à droite du bouton **Publier** en haut à droite
##### Choisir **Export HTML**
##### Sélectionner le dossier dans lequel créer l'export
::

L'éditeur crée un dossier `{identifiant de l'ePoc}-html` (par exemple `E006PE-html`) contenant :

- `index.html` : la page d'entrée
- `404.html` : copie de `index.html`, nécessaire aux hébergeurs comme GitLab Pages pour gérer les rafraîchissements sur une sous-page
- `assets/` : le lecteur ePoc ainsi que le contenu de votre ePoc

Le contenu du dossier est directement utilisable : il n'y a pas de dossier intermédiaire à retirer.

::alert{icon="lucide:info"}
Le site est relocalisable : il fonctionne à la racine d'un domaine comme dans un sous-chemin (`https://monorg.gitlab.io/mon-epoc/`).
::

## Héberger sur GitLab Pages

::steps{level=5}
##### Créer un dépôt GitLab et y copier le **contenu** du dossier exporté dans un dossier `public/`
##### Ajouter à la racine du dépôt un fichier `.gitlab-ci.yml` :
```yaml
pages:
  stage: deploy
  script:
    - echo "Publication de l'ePoc"
  artifacts:
    paths:
      - public
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
```
##### Une fois le pipeline terminé, l'ePoc est accessible depuis l'URL indiquée dans **Déploiement > Pages**
::

Lorsque vous ouvrez l'URL du site sans paramètre, le lecteur ajoute automatiquement l'identifiant de votre ePoc (`?epocId=...`), vous pouvez donc partager l'adresse telle quelle.

## Héberger sur GitHub Pages

::steps{level=5}
##### Créer un dépôt GitHub et y déposer le **contenu** du dossier exporté (`index.html`, `404.html` et `assets/` à la racine du dépôt)
##### Dans **Settings > Pages**, choisir **Deploy from a branch**, la branche principale et le dossier `/ (root)`
##### Après quelques instants, l'ePoc est accessible sur `https://{utilisateur}.github.io/{depot}/`
::

GitHub Pages sert automatiquement le fichier `404.html` pour les adresses inconnues, aucune configuration supplémentaire n'est nécessaire.

## Héberger sur un serveur web classique

Copiez le **contenu** du dossier exporté dans le dossier public de votre serveur (ou d'un sous-dossier). Le lecteur utilisant des URL sans `#`, le serveur doit renvoyer `index.html` pour les adresses qui ne correspondent à aucun fichier.

### Nginx

```nginx
server {
    listen 80;
    server_name epoc.example.org;
    root /var/www/mon-epoc;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

Pour un sous-dossier (`https://example.org/mon-epoc/`), utilisez `try_files $uri $uri/ /mon-epoc/index.html;` dans un `location /mon-epoc/`.

### Apache

Placez ce fichier `.htaccess` à côté de `index.html` (le module `mod_rewrite` et `AllowOverride All` doivent être activés) :

```apache
RewriteEngine On
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_FILENAME} !-d
RewriteRule . index.html [L]
```

::alert{icon="lucide:info"}
Comme pour GitLab Pages, ouvrir l'URL sans paramètre redirige automatiquement vers `?epocId=...`. Si vous servez l'ePoc depuis un serveur sans le fichier `index.html` modifié par l'éditeur (par exemple en le copiant à la main), pensez à conserver ce comportement.
::

## Tester en local

Le site doit être servi par un serveur web (l'ouverture directe de `index.html` ne fonctionne pas). Depuis le dossier exporté :

```shell
npx serve .
```
